## 简历描述（最终版）

**技术栈：** TypeScript + Next.js + LangChain + LangGraph + PostgreSQL + Prisma + Kafka + Elasticsearch + Redis + MinIO

**项目描述：** 基于 Monorepo 架构从零搭建企业级 RAG 知识库问答系统，实现了多模态文档解析、语义切分、多通道混合检索、异步索引管线、LLM 记忆压缩等功能，并内置 LangGraph ReAct Agent 作为复杂问题的兜底执行模式。

---

### 1. 混合检索融合

> 向量与关键词两通道并行召回后经倒数排名融合算法统一排序，无需归一化即可公平合并异构通道分数，解决了单通道召回不全和异构分数不可比的问题，提升了多源文档下的检索命中率。

### 2. 语义切分

> 逐句计算 embedding 并基于相邻句余弦相似度（阈值 0.8）动态切分文档，配合合并策略避免跨语义拼接，保证每块内容完整可读，解决了固定长度切分导致检索片段语义割裂的问题。

### 3. 异步处理管线

> 基于 Kafka 实现文档上传与解析索引的解耦，每阶段记录独立错误码与日志，支持失败自动重试（最多 3 次），解决大文档同步处理超时痛点，显著降低接口响应时间。

### 4. 记忆压缩

> 利用 LLM 定期将长对话历史压缩为摘要、事实及待解决问题结构化的 JSON，配合最近 4 轮原始对话组装上下文，有效控制上下文窗口，支持长对话不触发 Token 超限。

### 重点行号（retirevalEngine.ts）

- **第 7-28 行**：`rrfFusion` 函数，RRF 公式 `1/(k+rank+1)`，k=60
- **第 12 行**：`d${documentId}_c${chunkId}` 作为去重 key
- **第 31 行**：`Promise.all` 并行召回
- **第 27 行**：`slice(0, config.rag.finalTopK)` 取最终 TopK

### 核心代码

```typescript
function rrfFusion(a: RetrievalResult[], b: RetrievalResult[], k = 60): RetrievalResult[] {
    const m = new Map<string, {r: RetrievalResult, s: number}>();
    a.forEach((x, i) => {
        const key = `d${x.documentId}_c${x.chunkId}`;
        m.set(key, {r: x, s: 1 / (k + i + 1) });
    })
    b.forEach((x, i) => {
        const key = `d${x.documentId}_c${x.chunkId}`;
        const e = m.get(key);
        if(e) {
            e.s += 1 / (k + i + 1);
            if(x.score > e.r.score) e.r = x;
        }else m.set(key, { r: x, s: 1 / (k + i + 1) });
    })
    return Array.from(m.values()).sort((a, b) => b.s - a.s).slice(0, config.rag.finalTopK).map((x) => x.r);
}
```

### 面试必答

- **RRF 公式**：`score = Σ 1/(k + rank)`，rank 从 1 开始
- **k=60 为什么**：经典经验值，平滑排名靠后文档的得分差异，避免长尾被淹没
- **为什么不需要归一化**：RRF 只用排名（rank），不用原始分数，所以向量相似度（0~1）和 ES BM25 分数（可能 >1）天然可比
- **去重逻辑**：同一 chunk 在两通道都出现时，分数累加，保留分数高的那份内容

### 重点行号（embedding.ts）

- **第 26-38 行**：`splitIntoSentences` 按 `。！？.!?` 切句
- **第 41-55 行**：`cosineSimilarity` 余弦相似度计算
- **第 58-119 行**：`semanticSplit` 主逻辑

  - 第 80-96 行：超过 `maxChunkSize` 时按句二次拆分
- **第 122-151 行**：`splitTextBySemantic` 统一入口，Markdown 先按标题粗切再语义细切

### 核心代码

```typescript
export async function semanticSplit(text: string, threshould: number = 0.8, maxChunkSize: number = 1000): Promise<string[]> {
    const sentences = splitIntoSentences(text);
    const sentenceEmbeddings = await createEmbeddings(sentences);
    const breakpoints: number[] = [];
    for (let i = 0; i < sentenceEmbeddings.length - 1; i++) {
        const similarity = cosineSimilarity(sentenceEmbeddings[i], sentenceEmbeddings[i + 1]);
        if (similarity < threshould) {  // 相似度低于阈值，在此处切分
            breakpoints.push(i);
        }
    }
    // ... 后续合并逻辑
}
```

### 面试必答

- **阈值 0.8 怎么定**：实验调参，观察不同阈值下切分效果，0.8 是语义连贯性和切分粒度的平衡点
- **为什么用相邻句相似度**：相邻句语义突变处往往是话题切换点
- **maxChunkSize 作用**：防止语义连贯的大段落 chunk 过长，超过 1000 字按句二次拆分
- **Markdown 特殊处理**：先按 `#` 标题切 section，避免跨章节做 embedding 比较（不同章节本该切开）

### 核心代码

```typescript
// 重试逻辑
if (retryCount < AsyncProcessor.MAX_RETRIES) {
    await prisma.documentTask.update({
        where: { id: taskId },
        data: { retryCount: retryCount + 1, errorCode: 'PARSE_FAILED', errorMsg: err.message },
    });
    await producerService.sendParseRoute(documentId, taskId, objectName, retryCount + 1);
} else {
    // 超过重试次数，标记失败
    await prisma.superAgentDocument.update({
        where: { id: documentId },
        data: { parseStatus: 4, parseErrorMsg: err.message },
    });
}
```

### 面试必答

- **解耦点**：上传 API 只负责存 MinIO + 写 DB + 发 Kafka 消息，解析/索引由消费者异步处理
- **重试机制**：消息体带 `retryCount`，失败后重新入队并 +1，超过 3 次标记失败
- **幂等性**：任务表 `documentTask` 有唯一 taskId，重试时更新同一任务记录而非新建
- **一致性保证**：Kafka 发送失败时回滚 DB 操作（删除任务和文档），避免脏数据
- **为什么用 4 个消费者**：对应 Kafka 分区，并行提升吞吐

```typescript
// memorySummrizer.ts - LLM prompt
const r = await chatCompletion([
    {
        role: 'system',
        content: '你是一个记忆压缩助手。根据现有摘要和新的对话，输出 JSON: { "summary":"<500字摘要>", "stableFacts":[], "pendingQuestions":[], "retrievalHints":[], "conversationGoal":"", "resolvedPoints":[] }',
    },
    { role: 'user', content: `现有摘要: ${prev}，新的对话: ${transcript}` }
]);

// contextAssembler.ts - 触发条件
export function shouldCompress(latest: any, exchanges: { exchangeId: number }[]) {
    if(exchanges.length < 10) return false;
    const lastCompress = latest?.coveredExchangeId || 0;
    const latestId = exchanges[exchanges.length - 1].exchangeId;
    return latestId - lastCompress >= 10;
}
```

### 面试必答

- **触发时机**：`shouldCompress` 判断，对话累计满 10 轮且距上次压缩超过 10 轮时触发
- **上下文结构**：长期摘要（压缩后）+ 最近 4 轮原始对话，控制 Token 窗口
- **增量压缩**：`coveredExchangeId` 记录已压缩到哪一轮，下次只压缩新增部分
- **降级策略**：LLM 返回非合法 JSON 时，用 `transcript.slice(0, 500)` 兜底，保证流程不中断
- **JSON 字段含义**：`stableFacts`（稳定事实，如用户姓名）、`pendingQuestions`（待解决问题）、`retrievalHints`（检索提示）
